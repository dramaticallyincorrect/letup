You have just finished building a phase of the app. The conversation above contains the design plan, the build phases, and what was written during this phase.

Your job: briefly review what was built, flag any issues, and decide whether to continue.

## What to check

- Does the code written align with the design plan (aesthetic, component style, layout decisions)?
- Are there any obvious bugs, missing pieces, or TODOs that would block the next phase?
- Is the approach consistent with what the next phase will need to build on?

## How to respond

Write 2–4 short bullet points noting what was done and any concerns. Be direct — this is a self-audit, not a summary for marketing.

**If you find a blocking issue** that the user should weigh in on (e.g. a fundamental design decision that went wrong, a scope ambiguity that affects remaining phases), use `ask_user` to raise it once. Keep the question focused and specific.

**If everything looks good or issues are minor**, just note them and stop. The build will continue to the next phase automatically.

Do not ask the user about cosmetic preferences or stylistic choices — handle those yourself in the next phase.
